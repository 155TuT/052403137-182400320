# 拾伴 · 校园失物招领

软件工程结对作业，结对成员：052403137、182400320。使用 React + Vite，将拾伴原型中的首页、发布、搜索、详情与“我的”连接为可操作的前端程序。

本次实现围绕“发布信息 → 浏览或搜索 → 查看详情 → 联系发布者 → 发布者更新状态”。原型中的服务点、核验和奖励等内容用于说明设计来源，不代表已经接入真实的校内服务。

## 运行

开发环境需要 Node.js 22.12.0 或更新版本，以及随 Node.js 安装的 npm。首次安装依赖需要联网。

在项目根目录打开终端：

```powershell
npm install
npm run dev
```

使用 Google Chrome 打开终端显示的本地地址，通常是 `http://127.0.0.1:5173`；端口被占用时以实际输出为准。开发时请通过该地址访问，根目录的 `index.html` 是 Vite 开发入口。

运行数据与业务规则测试：

```powershell
npm test
```

生成供其他同学使用的网页：

```powershell
npm run build
```

构建输出在 `web/`。JavaScript 和 CSS 内联到 `web/index.html`，SVG 与字体保留在 `web/assets/`。分发时必须保留整个 `web` 文件夹。构建采用相对资源路径，供直接打开 HTML 使用。已在 Chrome 通过下面的本机预览方式验证同一份构建产物：

```powershell
npm run preview
```

在 Chrome 打开终端显示的地址，默认端口为 4173。开发服务、预览服务和双击 HTML 的浏览器数据彼此独立。修改源文件后先重新运行 `npm run build`，再刷新预览页。

## 使用与数据

- 首页显示招领与寻物记录，可以按关键词搜索，并结合类别、校区等条件筛选。搜索读取当前记录，新发布的内容也会参与搜索。
- 发布时选择寻物或招领，填写名称、类别、校区、区域和愿意公开的联系方式。日期不确定时可以留空；图片可选，最多 3 张 JPG / PNG，原始文件每张不超过 5 MB。
- 发布前可以保存草稿或查看公开预览。草稿不进入公开列表；继续编辑时保留已填信息。
- 详情展示当前记录和公开联系方式。复制失败时可选中文字手动复制。
- 当前演示用户是“小拾同学”。本人发布的招领可以标记“已归还”，寻物可以标记“已找到”；其他用户的记录不能由当前用户修改。结案后，列表与详情读取同一条更新后的记录。

首次打开时包含 3 条虚构示例：浅蓝折叠伞、银色钥匙串、黑色保温杯，以及水杯、钥匙、寻物、转报 4 条草稿。银色钥匙串属于当前演示用户，可用于练习状态更新。示例邮箱使用 `example.test`，并非真实联系人。

发布、草稿和状态保存在当前浏览器的 `localStorage`，键名为 `shiban-state-v1`，数据版本为 1。刷新同一打开地址后会继续读取这些数据；换浏览器、换设备、换地址或清除浏览器数据，不会自动迁移已有记录。开发地址与双击打开的文件也不共享一份数据。

本程序用于本地课程演示，没有服务器、真实账号认证或多人实时同步。本地用户身份和所有者检查用于演示业务规则，不能替代服务器权限控制。保存失败、存储空间不足或数据损坏时应保留错误提示，不把未保存的操作视为成功。

如需恢复初始示例，先确认不再需要当前数据，再在该页面的 Chrome 开发者工具 Console 中执行：

```javascript
localStorage.removeItem('shiban-state-v1');
location.reload();
```

这会清除当前打开地址下的拾伴演示数据，重新加载初始记录。

## 核心流程检查

以下步骤供测试人员复现。浏览器操作结果需要实际执行后记录，不能用组件存在或单元测试通过替代。

| 检查 | 操作 | 预期结果 |
| --- | --- | --- |
| 招领发布 | 发布一条“红色笔记本”，填写区域与 `demo@example.test`，预览后提交 | 出现在列表和“我的发布”，详情显示本次填写的内容 |
| 寻物发布 | 发布一条新的寻物信息，不添加照片 | 可以完成发布，详情类型与招领不同 |
| 自由搜索 | 搜索刚发布的完整名称，再搜索名称的一部分 | 能找到新记录，不局限于预置的雨伞、钥匙和水杯 |
| 筛选与空结果 | 设置类别或校区后重新搜索，再搜索不存在的物品 | 保留筛选条件；无结果时有明确提示，可以继续调整条件 |
| 字段校验 | 留空名称或联系方式，填写未来日期 | 指出具体错误，其他已填内容保留，不能直接发布 |
| 草稿恢复 | 填写表单并保存草稿，再从草稿箱继续编辑 | 恢复已保存内容，草稿不会出现在公开搜索中 |
| 联系发布者 | 打开有效信息详情并复制联系方式 | 显示发布者提供的文字；复制成功与失败反馈符合实际结果 |
| 本人结案 | 打开本人记录，先取消结案，再确认结案 | 取消不改变状态；确认后招领显示“已归还”，寻物显示“已找到” |
| 其他人的记录 | 打开蓝伞或水杯示例 | 可以查看公开内容，不能替发布者修改状态 |
| 保存与重开 | 发布或结案后刷新，再打开列表与详情 | 更新仍存在，各入口显示一致；已完成记录不能重复结案 |
| 重复操作与失败 | 连续点击提交；尝试不符合要求的图片 | 不重复创建同一次提交；图片问题明确反馈，不伪装成已保存 |

数据模块的自动化测试位于 `tests/model.test.js`，覆盖字段、日期和图片元数据校验，自由搜索与筛选，重复编号，所有者权限，结案幂等，草稿以及存储读写异常。测试数量和结果以 `npm test` 的实际输出为准。
